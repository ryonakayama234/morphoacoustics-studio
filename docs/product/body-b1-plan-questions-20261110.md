## 0. 再交渉しない前提

- B1 の製品操作は既存 OD-2 の限定離散操作のみ: 変形中心は声道区間 {4, 8}、倍率は {0.90, 1.00, 1.10}。全長変更・全体拡縮・自由な断面積編集は B1 に含めない。
- OD-2 の合法集合と検証済み revision は Core 側の研究実装に既に存在する。不足は「一般化」と「製品操作への昇格」であり、新しい物理の発明ではない。
- CC-B1 系譜（Studio ローカル、第9区間の断面積編集、未マージ Core ピン）は B1 と混ぜない。製品化の対象は Core の OD-2 のみ。
- RQ1 は厳密版 B の段階適用を継続する。Take の来歴は INCOMPLETE_PROVENANCE、full VERIFIED SOURCE は UNKNOWN のまま。音質の完全採用は別ゲートであり、B1 の計画は音質の主張を含まない。
- B0（現行 M0/M1 を製作された身体として再記述）は、S5 の限定ベースライン記録（Studio Issue #50）をもって実質充足している、という監督者整理を前提に置く。異論があれば QP4 で指摘すること。
- Studio の凍結スロット契約は変更しない。身体の選択 UI は inspector の「許可されたパラメータ」の範囲で設計する。新パネル・新モードは提案しない。
- 役割分担は従来どおり: 身体は到達可能な形状集合を制約する。エロさ・質感の責務分担（身体＝素質と傾向、運動＝演技、Scene＝関係、ニューラル＝埋め草）は QB10／PB7 の採用済み整理を維持し、B1 では扱わない。

## QP1 — OD-2 身体の同一性と Character からの参照形式

現行の Character body ref は `core_body_preset`（preset_id ∈ {M0, M1} + preset_revision + core_commit）のみ。OD-2 身体は preset ではなく「親 preset + 変形操作」の合成である。

- OD-2 身体を Character から参照する形式として何を推奨するか。現行 kind の拡張か、新しい kind か。操作列そのものを ref に埋め込むか、Core が発行した revision 識別子を参照するか。
- 同一性の判定基準: 同じ親 + 同じ操作なら同一身体として扱えるか。preparation digest（実測で一致を確認済みの準備過程の指紋）との関係をどう置くか。
- 検証済み revision が既に Core 側にある合法集合と、製品で選べる集合の対応をどう保つか（片方だけが増える事故を防ぐ仕組み）。

## QP2 — 実行経路: CC-A2 契約と façade の拡張

現行の唯一の物理実行経路は CC-A2 で、façade の許可身体は M0/M1 に固定されている（固定述語が 400 で弾く）。

- OD-2 身体を CC-A2 の v1 契約（embodiment は preset_id を受ける形）で実行する道筋を示すこと。契約の変更が要るなら、その最小形と版管理（v1 のままか、拡張か）を提案すること。
- façade の許可集合の拡張方法: ハードコードされた固定述語のまま OD-2 を足すのか、Core 側の合法集合を権威として参照する形にするのか。後者なら、その照合の失敗モード（Core と Studio の版ずれ）をどう fail-closed にするか。
- 実行前検証（身体の再読＋digest 照合、現行 façade が Character スナップショットに対して行っているもの）を OD-2 身体に対してどう拡張するか。

## QP3 — 検証ゲート: 「主張どおりの形状」を何で測るか

- OD-2 身体が主張どおりの形状であることを、どの測定で確認するか。形状そのものの再計算照合（区間列の一致）と、音響側の照合（共振ピーク等の凍結オラクル）のどちらを主ゲートにするか、両方か。
- S5 で M0 について成立した「raw pressure 量化 SHA が凍結オラクルと完全一致」という型の照合は、OD-2 身体にも用意できるか。用意できない身体については、主張をどこまで弱めるか。
- 600Hz 付近の未解明の観測（OD-2 系の既知の留保）の扱い: B1 のゲートに含めるか、既知の未解明として明示したうえで範囲外に置くか。

## QP4 — 段階分割と各段の受入条件

B1 を実装ステップに分割する提案を求める。想定する切り口（Core 側の発行・固定 → Studio の ref/façade 拡張 → UI の選択肢追加 → ベースライン採取の拡張）に対して:

- 段の順序と、各段の「完了」の定義（どの証拠が揃えば次へ進めるか）。
- 各段が独立に Owner GO を要するか、計画確定後は一括 GO でよいか、監督者の推奨を求める形で案を出すこと。
- B0 充足の監督者整理（前提 §0）への同意または反論。

## QP5 — UI の範囲（凍結スロット内）

- inspector で選べるのは中心 {4, 8} × 倍率 {0.90, 1.00, 1.10} の離散集合のみとし、自由な数値入力は置かない。この前提で、選択の提示方法（親身体との差分の見せ方、選んだ身体が何者かの参照表示）を提案すること。
- 現在の身体（M0/M1）と OD-2 身体の切り替えが、Character の改訂履歴（head.json + 不変 revision）にどう記録されるべきか。
- legacy 画面・研究系譜の表示との混線を避ける扱い（S4 で確立した正直表示の作法を維持する）。

## QP6 — ベースラインと主張の限界

- B1 で追加される身体について、限定ベースライン（身体同一性・形状物理の範囲、INCOMPLETE_PROVENANCE 明示）を S5 と同型に採取する計画を含めるか。
- B1 の完了時点で名乗れること・名乗れないことを、計画文書に明記する文案（例: 「OD-2 限定操作で作られた身体を製品で選択・保存・演技できる」までで、音質・質感の主張は含まない）。
