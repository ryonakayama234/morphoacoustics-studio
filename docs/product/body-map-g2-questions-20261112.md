# 質問票 BODYMAP-G2-20261112-01 — B2 受動損失の事前登録

**宛先**: Research Lead（ChatGPT）／ **審査**: 監督者（Muse）／ **決定**: Owner（中山）
**追跡**: Studio Issue #61 ／ **回答コード**: BODYMAP-G2-R-20261112-01（docs-only の Draft PR で回答）
**前提**: 身体モジュール地図（PR #57）と測定契約 v0（PR #60、成果物 E による凍結採用済み）が正本。凍結済み D の capability matrix では boundary は BLOCKED_BY_CAPABILITY で、本票はその解除に向けた事前登録の設計である。設計（事前登録の処方）のみで、実装・実験実施・Studio 変更は含まない。監督者の棚卸しでは、Core に損失の実装は現状なく、Fidelity 0 は無損失が契約（損失は語彙上の予約 `effect.viscothermal_loss` = UNMODELED としてのみ存在する）。

## QB2-1 — 損失モデルの処方
直列1D声道への粘性・熱損失（viscothermal）を、無損失・剛壁ベースラインとの差として定義できる形で処方してほしい。確定してほしい点:
- 定式化の選択（境界層型の複素波数／複素音速、等価な壁アドミタンス、その他）と、その選択理由・適用できる周波数と管径の範囲
- パラメータ集合（密度・音速・粘性・熱伝導・比熱比・温度など）と、その出所。身体モジュールとしてのパラメータの意味（モジュール S6 constitutive laws との対応）
- 既存の直列 tract・抵抗端子・0.20m プロキシとの合成方法。受動性（エネルギーを生まないこと）をどう保証し、どう検査するか
- 対象外の明示: 壁コンプライアンス・組織弾性・壁の運動は含まないこと（rigid-wall の置き換えではなく、損失の追加であること）

## QB2-2 — 実験設計（事前登録の中身）
結果を見る前に凍結すべき項目を、事前登録文書として提出できる粒度で処方してほしい:
- 対象の身体と条件（M0 を基本とし、M1／OD-2 形状を含めるか）と、介入の置き方（損失 on/off、パラメータの掃引をするなら段数と値）
- 主観測量（同一負荷での複素 transfer H/Z、raw Pa とその相対 L2、共鳴ピークの周波数と鋭さの変化、受動性／パワー収支）と、副次観測量の扱い（凍結済み特徴量 method は全て DEFINED_NOT_VALIDATED であるため、特徴量を合否に使わないことの確認）
- null 対照（損失パラメータ→0 で無損失ベースラインへ、事前に固定した許容差で復帰すること）と、mutation 対照（損失の符号反転＝利得化、パラメータのすり替え、負荷のすり替え等を検証器が拒否すること）
- 数値の許容差・周波数格子・判定基準を、結果を見る前にどう固定するか。独立オラクル（別の計算経路での transfer 評価など）の置き方

## QB2-3 — 実装経路と段の関門
Core に損失の実装がない前提で、処方してほしい:
- 損失つき計算を置く場所（Core 研究条件としての新パスか、既存ソルバへのオプションか）と、無損失の本線（Fidelity 0 契約・既存の受入済み結果）を壊さない分離の方法
- 実装に必要な作業の見取り図と、実装の受入条件（解析解や既知の参照ケースとの照合、受動性の検査、null 復帰の検査）
- 段の関門の区切り: 本ラウンドの事前登録採用 → 実装 GO → 実験実施 GO がそれぞれ別の Owner 判断であることの確認と、各段の成果物

## QB2-4 — 主張の制限と G0 契約との接続
- 新規ランを凍結済み take-metrology-pack/0 でどう記録するか（損失パラメータと定式化の版を pack のどこに残すか）。source 資格（二階建て）は不変であることの確認
- 実験が成功した場合に言える主張の上限（境界のあるモデル内での損失効果の実証までで、実在の身体の組織損失や音質の良さは主張しない）
- G0 の UNKNOWN 台帳・事前登録様式（成果物 D）との整合。D の capability matrix の boundary 行をどう更新するか（更新は本ラウンドの結論として提案し、凍結済み文書そのものは書き換えない）
